# Problem 73: Counting Fractions in a Range

https://projecteuler.net/problem=73

**Answer:** 7295372 · **Solution:** `P73.java` · **Runtime:** ~4.7 s

## Problem

Consider the fraction, n/d, where n and d are positive integers. If n < d and HCF(n, d) = 1, it is called a
reduced proper fraction.

If we list the set of reduced proper fractions for d ≤ 8 in ascending order of size, we get:

```
1/8, 1/7, 1/6, 1/5, 1/4, 2/7, 1/3, 3/8, 2/5, 3/7, 1/2, 4/7, 3/5, 5/8, 2/3, 5/7, 3/4, 4/5, 5/6, 6/7, 7/8
```

It can be seen that there are 3 fractions between 1/3 and 1/2.

How many fractions lie between 1/3 and 1/2 in the sorted set of reduced proper fractions for d ≤ 12,000?

## In Plain Terms

For each bottom number d up to 12,000, try every top number between d/3 and d/2 and count the ones that can't be
simplified. That's about 12 million fractions to check — a lot, but manageable.

## In Theory

For each d, count n with d/3 < n < d/2 and gcd(n, d) = 1. Summing over d gives the answer.

There's a lovely alternative using the **Stern–Brocot / Farey** structure: every fraction between two Farey
neighbours a/b and c/d is generated by repeatedly taking **mediants** (a+c)/(b+d). Since 1/3 and 1/2 are
neighbours, recursively counting mediants with denominator ≤ 12,000 counts exactly the reduced fractions in
between, with no gcd checks.

## In Code

1. For each `i` up to 12,000, step `numerator` from `i/3` while `numerator/i < 1/2`.
2. Count it if `numerator/i > 1/3` and `Divisors.isRelativelyPrime(numerator, i)`.

## Complexity

O(n²/6) candidate fractions, each with a coprimality check that factors both numbers — the cause of the
~5 s runtime. Space O(1).

## Further Thoughts

Swapping the factorization-based `isRelativelyPrime` for Euclid's `gcd(a, b)` (O(log n)) would make this many
times faster. The mediant recursion above is about 7 million calls and needs no gcd at all.

# Problem 35: Circular Primes

https://projecteuler.net/problem=35

**Answer:** 55 · **Solution:** `P35.java` · **Runtime:** ~0.13 s

## Problem

The number, 197, is called a circular prime because all rotations of the digits: 197, 971, and 719, are
themselves prime.

There are thirteen such primes below 100: 2, 3, 5, 7, 11, 13, 17, 31, 37, 71, 73, 79, and 97.

How many circular primes are there below one million?

## In Plain Terms

Take a prime, move its last digit to the front, and check if the result is still prime. Keep rotating until
you've tried every rotation. If they're all prime, it's a circular prime. Generate every prime under a million
once, store them where lookups are fast, and test each one's rotations.

## In Theory

Rotating n with d digits: move the last digit to the front,

```
rotate(n) = (n mod 10) × 10ᵈ⁻¹ + ⌊n / 10⌋
```

A d-digit number has d rotations (including itself). Any prime with more than one digit that contains an
even digit or a 5 has some rotation ending in that digit, which is then divisible by 2 or 5 — so circular
primes above 10 use only the digits 1, 3, 7, 9. That's a useful filter, though the code doesn't need it.

## In Code

1. Put every prime below 1,000,000 (`Primes.getPrimesUpUntil`) into a `TreeSet` for O(log n) membership tests.
2. For each prime, repeatedly rotate it (`num += 10^len × last digit; num /= 10`) and check the set,
   stopping at the first rotation that isn't prime.
3. Count the primes whose rotations all pass.

## Complexity

O(π(n) × d × log n) for the rotation checks, after generating the primes. Space O(π(n)) ≈ 78,000 primes.

## Further Thoughts

The rotation loop runs `num / 10` times rather than d − 1 times (and `num` changes inside the loop). Since
rotations repeat in a cycle, the extra iterations re-check the same numbers, so the result is still correct —
but a circular prime like 999331 is rotated about 100,000 times instead of 5. Looping over the digit count
fixes that, and a `boolean[]` sieve would make each lookup O(1).

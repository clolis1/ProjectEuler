# Problem 71: Ordered Fractions

https://projecteuler.net/problem=71

**Answer:** 428570 · **Solution:** `P71.java` · **Runtime:** ~0.24 s

## Problem

Consider the fraction, n/d, where n and d are positive integers. If n < d and HCF(n, d) = 1, it is called a
reduced proper fraction.

If we list the set of reduced proper fractions for d ≤ 8 in ascending order of size, we get:

```
1/8, 1/7, 1/6, 1/5, 1/4, 2/7, 1/3, 3/8, 2/5, 3/7, 1/2, 4/7, 3/5, 5/8, 2/3, 5/7, 3/4, 4/5, 5/6, 6/7, 7/8
```

It can be seen that 2/5 is the fraction immediately to the left of 3/7.

By listing the set of reduced proper fractions for d ≤ 1,000,000 in ascending order of size, find the numerator
of the fraction immediately to the left of 3/7.

## In Plain Terms

For each possible bottom number d up to a million, find the biggest fraction with that bottom that's still less
than 3/7 — that's just 3d/7 rounded down (one less if it lands exactly on 3/7). Of all those million
candidates, the one closest to 3/7 is the answer. No need to list trillions of fractions.

## In Theory

For each d, the best numerator below 3/7 is n = ⌊(3d − 1)/7⌋. The gap is

```
3/7 − n/d = (3d − 7n) / 7d  ≥  1 / 7d
```

with equality when 3d − 7n = 1. So the closest fractions come from the largest d with 3d ≡ 1 (mod 7), i.e.
d ≡ 5 (mod 7). The largest such d ≤ 10⁶ is 999,997, giving n = 428,570 (and 428570/999997 is already reduced).

This is also what **Farey sequences** predict: the left neighbour of a/b in a Farey sequence satisfies
bn − ad = 1.

## In Code

1. For each `i` up to 1,000,000, start at `numerator = 3i/7` and step up while still below 3/7.
2. If that fraction beats the closest so far and is reduced (`Divisors.isRelativelyPrime`), record it.

## Complexity

O(n) denominators with O(1) numerator steps each, plus a coprimality check on improvements. Space O(1).

## Further Thoughts

Comparing fractions as `double`s works at this size, but cross-multiplication (n₁·d₂ vs n₂·d₁, in `long`) is
exact. The closed form above solves it without a loop.

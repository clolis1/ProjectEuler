# Problem 31: Coin Sums

https://projecteuler.net/problem=31

**Answer:** 73682 · **Solution:** `P31.java` · **Runtime:** ~0.02 s

## Problem

In the United Kingdom the currency is made up of pound (£) and pence (p). There are eight coins in
general circulation:

```
1p, 2p, 5p, 10p, 20p, 50p, £1 (100p), and £2 (200p).
```

It is possible to make £2 in the following way:

```
1×£1 + 1×50p + 2×20p + 1×5p + 1×2p + 3×1p
```

How many different ways can £2 be made using any number of coins?

## In Plain Terms

Imagine emptying a jar of change onto a table and asking how many different piles add up to exactly £2.
"Different" means a different *mix* of coins — two 1p coins then a 2p is the same pile as a 2p then two 1p.

To avoid counting the same pile twice, decide the coins biggest-first: first choose how many £2 coins,
then how many £1 coins, and so on down to 1p. Each set of choices that lands exactly on 200p is
one way. At the very end, any leftover gap can always be filled with 1p coins in exactly one way.

## In Theory

This is the classic **coin-change counting** problem. Order doesn't matter, so we count *combinations*,
not sequences. The standard trick for that is to fix an order on the denominations and only ever use
coins in non-increasing size. Then every combination corresponds to exactly one path.

The recursion: let ways(t, k) be the number of ways to make total t using only the first k coin types.

```
ways(t, k) = ways(t, k−1)              (use no more coins of type k)
           + ways(t − coin[k], k)      (use one more coin of type k, and you may use more)
```

with ways(0, k) = 1 and ways(t < 0, k) = 0. The answer is ways(200, all 8 coins).

## In Code

`addcoins(total, order)` walks this tree, where `order` indexes into `coins = {1, 2, 5, …, 200}`:

1. First branch: if `order != 0`, recurse with `order − 1` — skip to smaller coins.
2. Second branch: add one `coins[order]` to `total`.
   - Exactly 200 → count it.
   - 199 while working with 2p coins (`order == 1`) → count it, since one 1p finishes it. This shortcut
     saves the last level of recursion.
   - Under 200 → recurse with the same `order` to try adding another coin of this size.
   - Over 200 → dead end; return.
3. The total lives in the static `total_combinations`, started by `addcoins(0, 7)`.

## Complexity

Exponential in general — it enumerates every combination one coin at a time. For £2 that's
about 2.9 million calls, most of them spent adding 1p coins one by one. Space is the recursion
depth, at most about 200 (a pile of all pennies).

## Further Thoughts

- The `199` shortcut generalizes: once you reach `order == 0`, *any* remaining gap is exactly one way
  (all 1p), so you could count it immediately instead of recursing one penny at a time. That alone
  cuts the work from ~2.9 million calls to ~147 thousand.
- The bottom-up dynamic-programming version is about five lines and runs in O(coins × target):
  ```
  ways = [1, 0, 0, …, 0]          (length 201)
  for each coin c:
      for t from c to 200:
          ways[t] += ways[t − c]
  ```
  Problems 76 and 77 reuse this exact pattern.

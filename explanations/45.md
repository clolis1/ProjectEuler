# Problem 45: Triangular, Pentagonal, and Hexagonal

https://projecteuler.net/problem=45

**Answer:** 1533776805 · **Solution:** `P45.java` · **Runtime:** < 0.01 s

## Problem

Triangle, pentagonal, and hexagonal numbers are generated by the following formulae:

```
Triangle     Tₙ = n(n+1)/2     1, 3, 6, 10, 15, ...
Pentagonal   Pₙ = n(3n−1)/2    1, 5, 12, 22, 35, ...
Hexagonal    Hₙ = n(2n−1)      1, 6, 15, 28, 45, ...
```

It can be verified that T₂₈₅ = P₁₆₅ = H₁₄₃ = 40755.

Find the next triangle number that is also pentagonal and hexagonal.

## In Plain Terms

We need a number that's on all three lists. Hexagonal numbers are the sparsest, so step through those starting
just after 143, and check each one against the other two. It turns out every hexagonal number is automatically
a triangle number, so really we only need to check "is it pentagonal?" — which has a formula.

## In Theory

**Every hexagonal number is triangular**: Hₙ = n(2n − 1) = (2n − 1)(2n)/2 = T₂ₙ₋₁. So we only need hexagonal
numbers that are also pentagonal.

A number x is pentagonal iff (1 + √(1 + 24x)) is divisible by 6 (see Problem 44).

The next one is H₂₇₆₉₃ = 1533776805 = T₅₅₃₈₅ = P₃₁₉₇₇.

## In Code

1. For `i` from 144 upward, compute `hexag = 2i² − i`.
2. Return the first one where `(1 + √(1 + 24·hexag)) % 6 == 0`.

## Complexity

O(m) where m is the index of the answer (about 27,500 steps). Space O(1).

## Further Thoughts

`1 + 24 × hexag` is a `long` here, but `Math.sqrt` returns a `double`. For values near 3.7 × 10¹⁰ that's still
exact, but past about 10¹⁵ a perfect-square check via `double` can misfire. An integer square root
(`Math.sqrt` then adjust ±1 and square-check) is the robust version.

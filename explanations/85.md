# Problem 85: Counting Rectangles

https://projecteuler.net/problem=85

**Answer:** 2772 · **Solution:** `P85.java` · **Runtime:** < 0.01 s

## Problem

By counting carefully it can be seen that a rectangular grid measuring 3 by 2 contains eighteen rectangles:

```
1×1: 6     2×1: 4     3×1: 2
1×2: 3     2×2: 2     3×2: 1      total 18
```

Although there exists no rectangular grid that contains exactly two million rectangles, find the area of the grid
with the nearest solution.

## In Plain Terms

Any rectangle drawn on the grid is set by choosing two of the vertical lines (its left and right sides) and two
of the horizontal lines (its top and bottom). That makes counting easy, so we can try grid sizes and keep the
one whose count lands closest to two million. The best is a 36 × 77 grid with 1,999,998 rectangles — area 2772.

## In Theory

An a × b grid has a + 1 vertical lines and b + 1 horizontal lines, so

```
rectangles(a, b) = C(a+1, 2) × C(b+1, 2) = T(a) × T(b)
```

where T(k) = k(k+1)/2 is the kth triangle number. Check the example: T(3) × T(2) = 6 × 3 = 18. ✓

So we want triangle numbers T(a), T(b) whose product is closest to 2,000,000. For each a, the best b is right where
T(a)·T(b) crosses 2 million — check the values just below and just above.

## In Code

1. For each `i` with T(i) < 2,000,000, increase `j` while T(i)·T(j) < 2,000,000, tracking the closest product and
   its area `i × j`.
2. After the inner loop, also check the first `j` that crosses 2,000,000 (the "just above" case).

## Complexity

O(√N log N) for N = 2,000,000 — each width a up to about √(2N) gets an inner loop of roughly 2√N / a steps, a few
thousand pairs in all. Space O(1).

## Further Thoughts

The "just above" check updates `closest` with `|2000000 − i × j|` (the area) instead of the rectangle count, so the
tracked distance is wrong after that branch fires. The answer still comes out right here, but the line should use
the same `T(i) × T(j)` expression as the inner loop. Also, since the computation is all whole numbers, `long`s
would be cleaner than `double`s.

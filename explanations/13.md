# Problem 13: Large Sum

https://projecteuler.net/problem=13

**Answer:** 5537376230 · **Solution:** `P13.java` · **Runtime:** < 0.01 s

## Problem

Work out the first ten digits of the sum of the following one-hundred 50-digit numbers.

(The hundred numbers, starting `37107287533902102798797998220837590246510135740250`, are listed in `P13.java`.)

## In Plain Terms

Adding a hundred 50-digit numbers by hand, you'd work right to left in columns, carrying as you go.
The code does the same, but in chunks of ten digits at a time instead of one. Each chunk is small enough
for the computer to add normally; only the "carry" passes to the next chunk to the left. When you reach the
leftmost chunk, its total (plus the carry) starts with the ten digits we want.

## In Theory

The total is about 5.5 × 10⁵¹, far beyond a 64-bit `long` (max ≈ 9.2 × 10¹⁸). But we can do
**long addition in base 10¹⁰**:

- Split each number into five 10-digit blocks.
- Add one block column at a time, right to left. A column of 100 blocks sums to at most
  100 × (10¹⁰ − 1) < 10¹², plus a carry — comfortably inside a `long`.
- The carry into the next column is ⌊column total / 10¹⁰⌋.

The leftmost column total plus its carry is a 12-digit number whose first ten digits are the answer.
(Strictly, only the first few blocks matter — the lower blocks can change the top digits only through the
carry, which the code tracks exactly.)

## In Code

1. For each block from the right (`i = 50, 40, 30, 20`), add `carryover` plus the 10-digit substring
   `[i−10, i)` of all hundred numbers; the new `carryover` is that subtotal divided by 10¹⁰.
2. Add the final carry to the sum of the leading 10-digit blocks.
3. Take the first ten characters of the result.

## Complexity

O(n × d) for n numbers of d digits — every digit is read once. Space O(1) beyond the input.

## Further Thoughts

`new BigInteger(...)` handles this in a few lines and is the go-to when the arithmetic itself isn't the point.

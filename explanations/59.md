# Problem 59: XOR Decryption

https://projecteuler.net/problem=59

**Answer:** 129448 · **Solution:** `P59.java` · **Runtime:** ~0.18 s

## Problem

Each character on a computer is assigned a unique code and the preferred standard is ASCII (American Standard
Code for Information Interchange). For example, uppercase A = 65, asterisk (\*) = 42, and lowercase k = 107.

A modern encryption method is to take a text file, convert the bytes to ASCII, then XOR each byte with a given
value, taken from a secret key. The advantage with the XOR function is that using the same encryption key on the
cipher text, restores the plain text; for example, 65 XOR 42 = 107, then 107 XOR 42 = 65.

For unbreakable encryption, the key is the same length as the plain text message, and the key is made up of
random bytes. The user would keep the encrypted message and the encryption key in different locations, and
without both "halves", it is impossible to decrypt the message.

Unfortunately, this method is impractical for most users, so the modified method is to use a password as a key.
If the password is shorter than the message, which is likely, the key is repeated cyclically throughout the
message. The balance for this method is using a sufficiently long password key for security, but short enough to
be memorable.

Your task has been made easy, as the encryption key consists of three lower case characters. Using
`data/p059_cipher.txt`, a file containing the encrypted ASCII codes, and the knowledge that the plain text must
contain common English words, decrypt the message and find the sum of the ASCII values in the original text.

## In Plain Terms

The message was scrambled with a three-letter password, repeated over and over. There are only 26 × 26 × 26 =
17,576 possible passwords, so try them all. The right one turns the gibberish into readable English, so score
each attempt by how much it looks like English — here, how many characters come out as letters or spaces — and
keep the best. Then add up the character codes of the decrypted text.

## In Theory

XOR is its own inverse: (p ⊕ k) ⊕ k = p. With a repeating 3-byte key, byte m is decrypted with key[m mod 3].

**Frequency scoring**: English text is dominated by letters and spaces (spaces alone are ~15–20% of characters),
while a wrong key produces scattered symbols. Counting letters and spaces separates the right key cleanly.
The key is "exp", and the text begins "An extract taken from the introduction of one of Euler's most celebrated
papers…".

## In Code

1. Read the comma-separated codes with `Resources.scanner`.
2. For every key `{i, j, k}` of lowercase letters, decrypt every byte, summing the plaintext values and counting
   letters and spaces as the score.
3. Keep the sum for the highest-scoring key.

## Complexity

O(26³ × n) for n ciphertext bytes (~1,400) — about 25 million XORs. Space O(n).

## Further Thoughts

- Each key letter only affects every third byte, so the three letters can be solved **independently**: for
  position 0, try all 26 letters on bytes 0, 3, 6, … and pick the most English-looking. That's 3 × 26 trials
  instead of 26³.
- **Bug fixed during the restructure**: the earlier version added both the encrypted and decrypted values
  (giving 176474), and picked the key by the largest sum over a hand-tuned set of "allowed" characters. With
  that fixed, a different key also passed the filter and gave 129459. Scoring by letters and spaces finds the
  right key.

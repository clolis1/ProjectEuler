# Problem 21: Amicable Numbers

https://projecteuler.net/problem=21

**Answer:** 31626 · **Solution:** `P21.java` · **Runtime:** ~0.02 s

## Problem

Let d(n) be defined as the sum of proper divisors of n (numbers less than n which divide evenly into n).
If d(a) = b and d(b) = a, where a ≠ b, then a and b are an amicable pair and each of a and b are called
amicable numbers.

For example, the proper divisors of 220 are 1, 2, 4, 5, 10, 11, 20, 22, 44, 55 and 110; therefore
d(220) = 284. The proper divisors of 284 are 1, 2, 4, 71 and 142; so d(284) = 220.

Evaluate the sum of all the amicable numbers under 10000.

## In Plain Terms

Add up all the numbers that divide into 220 (other than 220 itself) and you get 284. Do the same to 284 and
you get back to 220. Pairs like that are "amicable" — friendly numbers that point at each other. We work out
the divisor total for every number under 10,000, then look for pairs that point back at each other, ignoring
numbers that point at themselves (those are "perfect" numbers, like 6 = 1 + 2 + 3).

## In Theory

Compute d(n) for every n < 10000 by finding divisors in pairs up to √n (if i divides n, so does n/i).
Then n is amicable iff d(d(n)) = n and d(n) ≠ n.

There are five amicable pairs below 10000:

```
(220, 284)  (1184, 1210)  (2620, 2924)  (5020, 5564)  (6232, 6368)
```

## In Code

1. For each `i` in 1..9999, get all divisors with `Divisors.getDivisors(i)`, sum them, and subtract `i`
   to get d(i). Store it in the `nums_and_sums` table.
2. Walk the table: if d(i) is also a key, d(d(i)) = i, and d(i) ≠ i, add `i` to the total. Each member of
   a pair is added when its own entry is visited.

## Complexity

O(n√n) — √i trial divisions for each i < n. Space O(n) for the table.

## Further Thoughts

A **divisor-sum sieve** computes every d(n) at once: for each i, add i to every multiple 2i, 3i, … below n.
That's O(n log n). The old notes also point out that both checks could happen in a single pass.

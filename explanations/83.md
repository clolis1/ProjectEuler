# Problem 83: Path Sum: Four Ways

https://projecteuler.net/problem=83

**Answer:** 425185 · **Solution:** `P83.java` · **Runtime:** ~0.01 s

## Problem

In the 5 by 5 matrix below, the minimal path sum from the top left to the bottom right, by moving left, right, up,
and down, is marked with brackets and is equal to 2297.

```
[131]  673  [234] [103]  [18]
[201]  [96] [342]  965  [150]
 630   803   746  [422] [111]
 537   699   497  [121]  956
 805   732   524   [37] [331]
```

Find the minimal path sum from the top left to the bottom right by moving left, right, up, and down in matrix.txt
(`data/p083_matrix.txt`), a 31K text file containing an 80 by 80 matrix.

## In Plain Terms

With all four directions allowed, paths can wind around, so there's no simple fill order anymore. Instead, start
by assuming every cell is impossibly expensive to reach, except the start. Then repeatedly sweep the grid, letting
each cell lower its cost if a neighbour offers a cheaper route. When a full sweep changes nothing, every cell holds
its true cheapest cost.

## In Theory

This is a **shortest path** problem on a grid graph with non-negative cell weights. The code uses repeated
**relaxation** (the idea behind Bellman–Ford):

```
cost(cell) = min(cost(cell), grid(cell) + cost(neighbour))   for each of the four neighbours
```

repeated until nothing changes. It converges because costs only decrease and are bounded below.

**Dijkstra's algorithm** is the textbook tool: always expand the cheapest unsettled cell next, using a priority
queue. That settles each cell exactly once.

## In Code

1. Read the matrix with `Resources.reader`; `costs` is an 81×81 array filled with `Integer.MAX_VALUE` (the extra
   row and column act as a border so the code can look one step past the edge).
2. Sweep every cell, taking the minimum over its in-bounds neighbours plus its own value, and set `changesMade`
   when anything improves.
3. Repeat until a sweep makes no changes; return `costs[79][79]`.

## Complexity

O(n² × passes), where the number of passes depends on how winding the best paths are — a handful here.
Dijkstra would be O(n² log n). Space O(n²).

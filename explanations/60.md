# Problem 60: Prime Pair Sets

https://projecteuler.net/problem=60

**Answer:** 26033 · **Solution:** `P60.java` · **Runtime:** ~16 s

## Problem

The primes 3, 7, 109, and 673, are quite remarkable. By taking any two primes and concatenating them in any
order the result will always be prime. For example, taking 7 and 109, both 7109 and 1097 are prime. The sum of
these four primes, 792, represents the lowest sum for a set of four primes with this property.

Find the lowest sum for a set of five primes for which any two primes concatenate to produce another prime.

## In Plain Terms

Call two primes "friends" if gluing them together in either order — 7 and 109 make 7109 and 1097 — gives two
more primes. We want five primes that are all friends with each other, with the smallest possible total. Work
through primes in increasing order. For each new one, find which earlier primes it's friends with, then see if
it can join any existing friend-group whose members are all its friends, growing groups from 2 to 3 to 4 to 5.

## In Theory

This is finding a **5-clique** in a graph: primes are nodes, and an edge joins p and q when both pq and qp
(concatenated) are prime. We want the clique with the smallest sum.

The answer is {13, 5197, 5701, 6733, 8389}, summing to 26033.

Pruning comes from the sum: once a 5-set with sum S is known, any new prime p with p + (the smallest possible
sum of the other four) ≥ S can't help, so the search can stop.

## In Code

1. Generate primes one at a time by trial division (`counter`).
2. For each new prime, test concatenation with every earlier prime (`Primes.isPrime` on both orders) to build
   its `prime_pairs`, and record each pair as a 2-set.
3. For sizes 4 down to 2, extend every existing i-set whose members are all in `prime_pairs` with the new prime,
   and update `lowest_sums[i + 1]`.
4. Stop when `counter + lowest_sums[4]` reaches `lowest_sums[5]`.

## Complexity

Roughly O(P² × √C): every pair of primes up to the stopping point P gets two primality tests on concatenations
C (up to ~10⁸). Plus the set extensions, which can grow large — the slowest part of the 16 s. Space O(number of
partial cliques).

## Further Thoughts

The usual faster approach: build the adjacency once for primes below ~10,000 (caching pair results), then do a
depth-first clique search where each new member must be adjacent to all current members, pruning on the
running sum. That typically runs in well under a second. Also, primes ≡ 1 and ≡ 2 (mod 3) can't be mixed
(their concatenation's digit sum would be divisible by 3), which splits the graph in two.

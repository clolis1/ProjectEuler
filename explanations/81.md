# Problem 81: Path Sum: Two Ways

https://projecteuler.net/problem=81

**Answer:** 427337 · **Solution:** `P81.java` · **Runtime:** < 0.01 s

## Problem

In the 5 by 5 matrix below, the minimal path sum from the top left to the bottom right, by only moving to the
right and down, is marked with brackets and is equal to 2427.

```
[131] 673   234   103    18
[201] [96] [342]  965   150
 630   803 [746] [422]  111
 537   699  497  [121]  956
 805   732  524   [37] [331]
```

Find the minimal path sum from the top left to the bottom right by only moving right and down in matrix.txt
(`data/p081_matrix.txt`), a 31K text file containing an 80 by 80 matrix.

## In Plain Terms

Like the triangle problems (18 and 67), but on a grid. You can only arrive at a square from the left or from
above, so the cheapest way to reach it is its own value plus whichever of those two neighbours was cheaper to
reach. Fill the grid in that way, row by row, and the bottom-right square holds the answer.

## In Theory

**Dynamic programming** on a grid:

```
cost(0, 0) = grid(0, 0)
cost(i, j) = grid(i, j) + min(cost(i−1, j), cost(i, j−1))      (only one option on the top row / left column)
```

Since moves only go right or down, every cell's predecessors are already computed when filling row by row.

## In Code

1. Read each row with `Resources.reader`, splitting on commas.
2. As each row is read, overwrite `grid` in place with cumulative costs: the first row and column accumulate
   along the edge; interior cells take the minimum of left and above.
3. Return `grid[79][79]`.

## Complexity

O(n²) for an n×n grid. Space O(n²) (or O(n) keeping one row).

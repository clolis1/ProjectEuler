# Problem 78: Coin Partitions

https://projecteuler.net/problem=78

**Answer:** 55374 · **Solution:** `P78.java` · **Runtime:** ~0.32 s

## Problem

Let p(n) represent the number of different ways in which n coins can be separated into piles. For example, five
coins can be separated into piles in exactly seven different ways, so p(5) = 7.

```
OOOOO
OOOO   O
OOO   OO
OOO   O   O
OO   OO   O
OO   O   O   O
O   O   O   O   O
```

Find the least value of n for which p(n) is divisible by one million.

## In Plain Terms

p(n) — the number of ways to split n into piles — grows astronomically fast, so we can't store it exactly for
large n. But we only need to know when it's divisible by a million, which only depends on its last six digits.
And there's a famous formula, discovered by Euler, that computes each p(n) from a handful of earlier values.
Use that formula, keep only the last six digits at each step, and stop at the first p(n) ending in 000000.

## In Theory

The coin-change DP from Problem 76 is O(n²) per value — too slow when n reaches tens of thousands. Euler's
**pentagonal number theorem** gives a much faster recurrence:

```
p(n) = Σ (−1)^(k+1) · p(n − gₖ)   over k = 1, −1, 2, −2, 3, −3, …
gₖ = k(3k − 1)/2                   (generalized pentagonal numbers: 1, 2, 5, 7, 12, 15, …)
```

with signs + + − − + + − − …. Only about √n terms are non-zero, and since we work **mod 10⁶**, every value stays
small.

## In Code

1. `p` is a growing list with `p[0] = 1`.
2. For each new `target`, walk the generalized pentagonal numbers `penta` (k alternating 1, −1, 2, −2, …) while
   `penta ≤ target`, adding or subtracting `p[target − penta]` by the sign pattern `i % 4 > 1`, and reducing
   mod 1,000,000.
3. Stop at the first `target` where `p[target] == 0`.

## Complexity

O(n√n) — about √n terms for each n up to 55,374. Space O(n).

## Further Thoughts

Java's `%` keeps the sign of the left operand, so `p[target]` can go negative mid-sum. That's fine for detecting
0 at the end, but adding 1,000,000 before taking `%` keeps values in 0..999999 throughout.

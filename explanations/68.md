# Problem 68: Magic 5-gon Ring

https://projecteuler.net/problem=68

**Answer:** 6531031914842725 · **Solution:** `P68.java` · **Runtime:** ~0.39 s

## Problem

Consider the following "magic" 3-gon ring, filled with the numbers 1 to 6, and each line adding to nine.

```
        4
         \
          3
         / \
        1 - 2 - 6
       /
      5
```

Working clockwise, and starting from the group of three with the numerically lowest external node (4,3,2 in this
example), each solution can be described uniquely. For example, the above solution can be described by the set:
4,3,2; 6,2,1; 5,1,3.

It is possible to complete the ring with four different totals: 9, 10, 11, and 12. There are eight solutions in
total.

```
Total   Solution Set
9       4,2,3; 5,3,1; 6,1,2
9       4,3,2; 6,2,1; 5,1,3
10      2,3,5; 4,5,1; 6,1,3
10      2,5,3; 6,3,1; 4,1,5
11      1,4,6; 3,6,2; 5,2,4
11      1,6,4; 5,4,2; 3,2,6
12      1,5,6; 2,6,4; 3,4,5
12      1,6,5; 3,5,4; 2,4,6
```

By concatenating each group it is possible to form 9-digit strings; the maximum string for a 3-gon ring is
432621513.

Using the numbers 1 to 10, and depending on arrangements, it is possible to form 16- and 17-digit strings. What is
the maximum 16-digit string for a "magic" 5-gon ring?

## In Plain Terms

Picture a pentagon with five spokes sticking out. Place the numbers 1–10 on the ten spots so that every spoke —
outer number plus two inner numbers — adds to the same total. Then read the arrangement as one long number. We try
every arrangement, keep the valid ones, and take the largest reading. For a 16-digit result, 10 has to sit on the
outside, since outer numbers are written once and inner numbers twice.

## In Theory

- Each inner node appears in two lines, each outer node in one. 10 has two digits, so a 16-digit string needs 10
  on an **outer** node (4 single digits × 2 + 5 outer digits + one extra digit for 10 = 16).
- To get the largest string, the starting (smallest) outer node should be as large as possible — ideally 6, which
  happens when the outer ring is {6, 7, 8, 9, 10} and the inner ring is {1, …, 5}. Then each line totals
  (2 × 15 + 40) / 5 = 14.

The best arrangement reads 6,5,3; 10,3,1; 9,1,4; 8,4,2; 7,2,5 → 6531031914842725.

## In Code

1. Positions: `perm[0, 3, 5, 7, 9]` are outer nodes, `perm[1, 2, 4, 6, 8]` inner; each line is
   outer + two adjacent inner nodes.
2. Step through all 10! permutations with `Lexography.nextPermutation`.
3. Skip if 10 is inner, if `perm[0]` isn't the smallest outer node (fixing a unique starting point), or if any
   line total differs.
4. Keep the lexicographically largest description string.

## Complexity

O(n!) — all 3,628,800 permutations of 10 numbers, constant work each. Space O(n).

## Further Thoughts

The reasoning above settles the outer and inner sets, which leaves only 4! × 5! arrangements to check — or
pen-and-paper.

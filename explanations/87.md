# Problem 87: Prime Power Triples

https://projecteuler.net/problem=87

**Answer:** 1097343 · **Solution:** `p087.py` · **Runtime:** ~1.2 s

## Problem

The smallest number expressible as the sum of a prime square, prime cube, and prime fourth power is 28. In fact,
there are exactly four numbers below fifty that can be expressed in such a way:

```
28 = 2² + 2³ + 2⁴
33 = 3² + 2³ + 2⁴
49 = 5² + 2³ + 2⁴
47 = 2² + 3³ + 2⁴
```

How many numbers below fifty million can be expressed as the sum of a prime square, prime cube, and prime fourth
power?

## In Plain Terms

We want numbers that can be built as one prime squared, plus one prime cubed, plus one prime to the fourth power.
My first worry was that checking every number up to fifty million would take forever, but it turns out you don't
need to: the powers grow so fast that only a few dozen primes can be cubed or raised to the fourth power, and
under a thousand can be squared. So I flip it
around and build every possible sum from those primes, dropping each one into a set. A set only keeps one copy of
each number, which matters because some numbers can be built in more than one way. The answer is how many
numbers end up in the set.

## In Theory

**How big can each prime be?** Every term is positive, so each one alone has to be below fifty million:

```
p² < 50,000,000   →  p < 7,071   →  908 primes
q³ < 50,000,000   →  q < 368     →   73 primes
r⁴ < 50,000,000   →  r < 84      →   23 primes
```

That's at most 908 × 73 × 23 ≈ 1.5 million combinations, and stopping each loop as soon as the sum reaches fifty
million cuts it to about 1.14 million. Small enough to try them all.

**Count numbers, not combinations.** Different prime triples can give the same total. Of the 1,139,575 combinations
under the limit, only 1,097,343 distinct numbers come out, so about 42,000 totals are reached more than once.
Counting combinations instead of numbers would overshoot. A **hash set** keeps each total once.

**The example:** below 50 the only sums are 28 = 2² + 2³ + 2⁴, 33 = 3² + 2³ + 2⁴, 47 = 2² + 3³ + 2⁴ and
49 = 5² + 2³ + 2⁴.

## In Code

1. List the primes below √limit with `sympy.primerange`. That covers the squares, and the cube and fourth-power
   loops use the same list.
2. Three nested loops: prime for the square (outer), cube (middle), fourth power (inner). Each loop **breaks**
   as soon as the partial sum reaches the limit, since the primes are in increasing order and every later one
   would be bigger still.
3. Add each total below the limit to a `set`, and return its size.

"Below fifty million" is strict, so a total of exactly 50,000,000 isn't counted.

## Complexity

About 1.1 million additions and set insertions, and the set holds about 1.1 million numbers.
Roughly O(π(√L) × π(∛L) × π(L^¼)) for a limit L. It takes about 1.2 s, most of it Python's loop overhead.

## Further Thoughts

- A `bytearray` of length fifty million, marking each total with a 1 and counting the 1s at the end, avoids
  hashing and runs a bit faster, for about the same memory (around 50 MB either way). At this size the set is fine.
- Ordering the loops from biggest power to smallest (fourth power outside, square inside) means the innermost
  loop runs over the most primes, so each break saves the most work. It makes little difference here.

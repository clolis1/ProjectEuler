# Problem 7: 10001st Prime

https://projecteuler.net/problem=7

**Answer:** 104743 · **Solution:** `P7.java` · **Runtime:** ~0.02 s

## Problem

By listing the first six prime numbers: 2, 3, 5, 7, 11, and 13, we can see that the 6th prime is 13.

What is the 10 001st prime number?

## In Plain Terms

Count upward and test each number to see whether anything smaller divides it. You only need to try
dividing by the primes found so far, and only up to the number's square root: divisors come in pairs
(like 3 × 12 = 36), and one of each pair is always at most the square root. Keep going until you've
collected 10,001 primes.

## In Theory

A number n > 1 is prime iff no prime p ≤ √n divides it. If n = a × b with a ≤ b, then a² ≤ ab = n, so
a ≤ √n — and a's smallest prime factor is even smaller. That gives **trial division by primes**.

How far do we need to search? The prime number theorem says the kth prime is roughly k ln k; for
k = 10001 that's about 92,000, and the actual answer is 104,743.

## In Code

1. Seed `primes` with 2 and 3, and start testing at 4.
2. For each candidate, divide by `primes.get(i)` while that prime is ≤ √candidate. Any exact division
   means composite.
3. Survivors are appended to `primes`. Stop when the list has 10,001 entries and return `primes.get(10000)`.

## Complexity

Each test costs O(π(√n)) ≈ O(√n / ln n) divisions, for about n ≈ 10⁵ candidates — a few million
operations. Space O(k) for the list of primes.

## Further Thoughts

A **Sieve of Eratosthenes** up to an estimated bound (e.g. k(ln k + ln ln k) ≈ 115,000) is the standard
faster approach. Skipping even candidates would also halve the work.

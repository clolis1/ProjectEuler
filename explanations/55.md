# Problem 55: Lychrel Numbers

https://projecteuler.net/problem=55

**Answer:** 249 · **Solution:** `P55.java` · **Runtime:** ~0.08 s

## Problem

If we take 47, reverse and add, 47 + 74 = 121, which is palindromic.

Not all numbers produce palindromes so quickly. For example,

```
349 + 943 = 1292
1292 + 2921 = 4213
4213 + 3124 = 7337
```

That is, 349 took three iterations to arrive at a palindrome.

Although no one has proved it yet, it is thought that some numbers, like 196, never produce a palindrome. A
number that never forms a palindrome through the reverse and add process is called a Lychrel number. Due to
the theoretical nature of these numbers, and for the purpose of this problem, we shall assume that a number is
Lychrel until proven otherwise. In addition you are given that for every number below ten-thousand, it will
either (i) become a palindrome in less than fifty iterations, or, (ii) no one, with all the computing power that
exists, has managed so far to map it to a palindrome. In fact, 10677 is the first number to be shown to require
over fifty iterations before producing a palindrome: 4668731596684224866951378664 (53 iterations, 28-digits).

Surprisingly, there are palindromic numbers that are themselves Lychrel numbers; the first example is 4994.

How many Lychrel numbers are there below ten-thousand?

## In Plain Terms

Take a number, flip its digits around, and add the two together. Keep doing that until you get a number that
reads the same both ways. Most numbers get there fast, but some seem to go on forever. The problem tells us
that under 10,000, anything that hasn't made a palindrome within 50 rounds never will (as far as anyone knows),
so we try 50 rounds for each number and count the ones that never get there.

## In Theory

Each step roughly doubles the number, so after 50 steps values reach around 25+ digits, beyond a `long` —
hence `BigInteger`.

Note the rule says "at least one iteration": the starting number being a palindrome doesn't count (4994 is
Lychrel). The check only happens **after** each reverse-and-add.

## In Code

1. For each `i` below 10,000, repeat up to 50 times: reverse the decimal string, add it as a `BigInteger`, and
   stop if the result is a palindrome (`Digits.isPalindrome`).
2. Count `i` if all 50 iterations fail.

## Complexity

O(n × k × d) for n starting numbers, k = 50 iterations and d-digit arithmetic. Space O(d).

# Problem 88: Product-sum Numbers

https://projecteuler.net/problem=88

**Answer:** 7587457 · **Solution:** `p088.py` · **Runtime:** ~0.17 s

## Problem

A natural number, N, that can be written as the sum and product of a given set of at least two natural numbers,
{a₁, a₂, …, aₖ}, is called a product-sum number: N = a₁ + a₂ + … + aₖ = a₁ × a₂ × … × aₖ.

For example, 6 = 1 + 2 + 3 = 1 × 2 × 3.

For a given set of size, k, we shall call the smallest N with this property a minimal product-sum number. The
minimal product-sum numbers for sets of size, k = 2, 3, 4, 5, and 6 are as follows.

```
k=2:  4 = 2 × 2                 = 2 + 2
k=3:  6 = 1 × 2 × 3             = 1 + 2 + 3
k=4:  8 = 1 × 1 × 2 × 4         = 1 + 1 + 2 + 4
k=5:  8 = 1 × 1 × 2 × 2 × 2     = 1 + 1 + 2 + 2 + 2
k=6: 12 = 1 × 1 × 1 × 1 × 2 × 6 = 1 + 1 + 1 + 1 + 2 + 6
```

Hence for 2 ≤ k ≤ 6, the sum of all the minimal product-sum numbers is 4 + 6 + 8 + 12 = 30; note that 8 is only
counted once in the sum.

In fact, as the complete set of minimal product-sum numbers for 2 ≤ k ≤ 12 is {4, 6, 8, 12, 15, 16}, the sum is 61.

What is the sum of all the minimal product-sum numbers for 2 ≤ k ≤ 12000?

## In Plain Terms

Every one of these sets is a small handful of numbers with a pile of 1s tacked on. The 1s are the trick: adding a 1
raises the sum but leaves the product alone. So pick any way of multiplying up to N, like 24 = 2 × 3 × 4, and add
exactly enough 1s to bring the sum up to N as well. Each different way of splitting N into factors gives a set of a
different size, which is why one number like 24 can be the answer for five different set sizes at once.

So instead of searching for each set size separately, I go through the numbers 4, 5, 6, … in order, try every way
of splitting each one, and note which set sizes it reaches. The first number to reach a given size is that size's
answer, since every number after it is bigger.

## In Theory

**From a factorization to a set size.** Write N as a product of factors ≥ 2, say with m factors adding up to s.
Padding with (N − s) ones makes the sum N too, so the set has

```
k = m + (N − s)        (the factors, plus the 1s)
```

Both parts count. 32 = 2 × 2 × 2 × 2 × 2 needs 22 ones, but k = 5 + 22 = **27**, not 22. And 24 splits five ways:

```
3 × 8          k = 2 + (24 − 11) = 15
4 × 6          k = 2 + (24 − 10) = 16
2 × 2 × 6      k = 3 + (24 − 10) = 17
2 × 3 × 4      k = 3 + (24 −  9) = 18
2 × 2 × 2 × 3  k = 4 + (24 −  9) = 19
```

**Smallest N wins.** Several N reach the same k (8 and 9 both reach k = 5), and the minimal one is just the smallest.
Going through N in increasing order, the first time any factorization reaches k, that N is k's minimal product-sum
number, so each answer is written once and never replaced. There's no tidy formula for which splitting lands on which
k, so trying them all is the way; bigger numbers end up only filling in the k's that smaller ones missed.

**Why it finishes quickly.** Every k has *some* product-sum set: {2, k, and k − 2 ones} has sum and product both 2k.
So no minimal N is bigger than 2k, which caps the search at 24,000 for k ≤ 12,000. In practice every k up to 12,000 is
filled by N = 12,200.

**Distinct values only.** The question sums the *different* minimal numbers, so 8 counts once even though it's the
answer for k = 4 and k = 5. For k ≤ 12 that's {4, 6, 8, 12, 15, 16} → 61.

## In Code

1. `minimal_product_sums(k_max)` keeps a `best` array with one slot per k, and walks N = 4, 5, 6, … filling each
   empty slot that N reaches, until every slot from 2 to `k_max` is filled.
2. `set_sizes(n, k_max)` lists every k that n reaches. Its recursive `split` builds factorizations with factors in
   non-decreasing order (2 × 2 × 6 but never 6 × 2 × 2), so each one appears exactly once. For each, it computes
   k = factors + (n − sum).
3. Pruning: splitting further only adds factors and lowers the sum, so k only grows. As soon as a k passes
   `k_max`, that branch stops, and so does the loop over bigger factors, since a bigger first factor means a smaller
   sum.
4. `sum_of_minimal` adds up the `set()` of the filled slots, so repeated values count once.

## Complexity

N goes up to about 12,200, and each N has only a handful of factorizations within range (most N have very few), so
the total work is a few hundred thousand factorization steps. About 0.17 s.

## Further Thoughts

- **A detour worth keeping:** the first few runs of equal answers (1, 1, 2, 3 for 4, 6, 8, 12) look like Fibonacci,
  but the pattern breaks straight after (15 covers one k, 16 covers three, 24 covers five), and the answers aren't
  even always increasing: k = 24 needs 48, but k = 25 only needs 32. Small cases can look like famous sequences;
  checking further is the only way to know.
- **Credit:** the k formula, "smallest N wins" and filling slots in increasing order were my own reasoning; the
  2k ceiling came from a nudge.
- The "fill in increasing order, so the first hit is the best" pattern is a reusable one: it turns "find the minimum
  for every k" into a single pass with no comparisons.

# Problem 43: Sub-string Divisibility

https://projecteuler.net/problem=43

**Answer:** 16695334890 · **Solution:** `P43.java` · **Runtime:** ~0.25 s

## Problem

The number, 1406357289, is a 0 to 9 pandigital number because it is made up of each of the digits 0 to 9 in
some order, but it also has a rather interesting sub-string divisibility property.

Let d₁ be the 1st digit, d₂ be the 2nd digit, and so on. In this way, we note the following:

```
d₂d₃d₄  = 406 is divisible by 2
d₃d₄d₅  = 063 is divisible by 3
d₄d₅d₆  = 635 is divisible by 5
d₅d₆d₇  = 357 is divisible by 7
d₆d₇d₈  = 572 is divisible by 11
d₇d₈d₉  = 728 is divisible by 13
d₈d₉d₁₀ = 289 is divisible by 17
```

Find the sum of all 0 to 9 pandigital numbers with this property.

## In Plain Terms

There are about 3.6 million ways to arrange the digits 0–9. For each one, slide a three-digit window along it
and check that the windows are divisible by 2, 3, 5, 7, 11, 13 and 17 in turn. Some checks are nearly free —
"divisible by 2" only depends on the window's last digit being even. Only six arrangements pass every test.

## In Theory

Some conditions reduce to single digits:

- d₂d₃d₄ divisible by 2 ⇔ **d₄ is even**.
- d₄d₅d₆ divisible by 5 ⇔ **d₆ is 0 or 5**.

The six numbers are 1406357289, 1430952867, 1460357289, 4106357289, 4130952867 and 4160357289.

## In Code

1. Generate all permutations of "0123456789" in sorted order (`Lexography.sortedPermutations`).
2. Skip the first tenth (those starting with 0).
3. Check d₄ even, d₆ divisible by 5, then the five three-digit substrings mod 3, 7, 11, 13, 17; sum the
   survivors as `long`s.

## Complexity

O(n! × n) — all 10! = 3,628,800 permutations, each with constant-size checks. Space O(n!) to hold them.

## Further Thoughts

Building numbers right to left — start with three-digit multiples of 17 with distinct digits, then prepend a
digit so the new window is divisible by 13, and so on — prunes almost everything immediately and visits only
a few hundred partial numbers.

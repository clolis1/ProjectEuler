# Problem 86: Cuboid Route

https://projecteuler.net/problem=86

**Answer:** 1818 · **Solution:** `p086.py` · **Runtime:** < 0.01 s

## Problem

A spider, S, sits in one corner of a cuboid room, measuring 6 by 5 by 3, and a fly, F, sits in the opposite
corner. By travelling on the surfaces of the room the shortest "straight line" distance from S to F is 10 and the
path is shown on the diagram. (The site's diagram shows the 6 × 5 × 3 room with the spider's route drawn across
its surfaces.)

However, there are up to three "shortest" path candidates for any given cuboid and the shortest route doesn't
always have integer length.

It can be shown that there are exactly 2060 distinct cuboids, ignoring rotations, with integer dimensions, up to a
maximum size of M by M by M, for which the shortest route has integer length when M = 100. This is the least value
of M for which the number of solutions first exceeds two thousand; the number of solutions when M = 99 is 1975.

Find the least value of M such that the number of solutions first exceeds one million.

## In Plain Terms

Picture the room as a cardboard box. The spider has to walk on the walls, floor and ceiling, so the trick is to
unfold the box flat: the two faces the spider crosses become one big rectangle, and the shortest walk is a
straight line across it, the diagonal of that rectangle. There are three ways to pick the pair of faces, and the
shortest route always keeps the room's **longest** side on its own while the other two sides join up to make the
rectangle's other edge.

So for each room, the question becomes: is that diagonal a whole number? Rather than check every room for every
size, I count size by size: when the room limit grows from M − 1 to M, the only new rooms are the ones whose
longest side is exactly M. I keep a running total and stop the first time it passes a million.

## In Theory

**One room.** Sort the sides a ≤ b ≤ c. Unfolding two faces gives a rectangle, and there are three candidates,
depending on which side stays alone:

```
√(c² + (a + b)²)      √(b² + (a + c)²)      √(a² + (b + c)²)
```

The first is always the shortest. Expanding the squares, everything matches except 2ab vs 2bc vs 2ac, and since
a ≤ b ≤ c, 2ab is the smallest. For the statement's room: √(6² + (5 + 3)²) = √100 = **10**, against √106 and √130.

It only matters whether the *shortest* route is a whole number. A longer candidate being whole doesn't count.

**When does a room count?** Writing s = a + b, the room counts when c² + s² is a perfect square: c and s are the
two legs of a Pythagorean triple. A room is counted exactly once, at the M equal to its longest side, so nothing
has to be remembered from earlier sizes.

**From a triple to rooms.** For a fixed c, each valid s gives one room per way of splitting s = a + b with
1 ≤ a ≤ b ≤ c:

```
s ≤ c:   ⌊s/2⌋                  (a = 1 … ⌊s/2⌋)
s > c:   ⌊s/2⌋ − (s − c) + 1    (a = s − c … ⌊s/2⌋, so b never exceeds c)
```

Two easy mistakes here: using ⌊s/2⌋ when s > c counts splits where b is longer than c (for c = 6, s = 8, the split
1 + 7 isn't allowed), and forgetting the **+ 1** for an inclusive count (2 + 6, 3 + 5, 4 + 4 is 3 rooms, not 2).

Also, c can be either leg. With 3-4-5:

```
c = 3, s = 4:   1 × 3 × 3,  2 × 2 × 3      (c is the shorter leg)
c = 4, s = 3:   1 × 2 × 4                  (c is the longer leg)
```

**Generating the triples instead of searching for them.** Testing every (c, s) pair works, but almost none of
them are triples. **Euclid's formula** produces them directly: for m > n > 0, coprime and not both odd,
(m² − n², 2mn, m² + n²) is a primitive triple, every primitive triple comes from exactly one such pair, and every
other triple is a whole-number multiple of one. Since we don't know the final M in advance, I start with a size
limit of 50 and double it until the count passes a million (50, 100, … 3200).

The count first passes a million at **M = 1818** (999,850 rooms at M = 1817; 1,000,457 at M = 1818).

## In Code

1. `least_m_exceeding(target)` starts with `limit = 50`. For each limit it gets the number of rooms for every
   longest side up to the limit, adds them up in order, and returns the first M where the total passes the target.
   If it never does, it doubles the limit and tries again.
2. `rooms_by_longest_side(limit)` builds that per-M count. It asks `euler.lib.pythagorean_triples` for every triple
   with shorter leg x ≤ limit and longer leg y ≤ 2 × limit, the only ones that can make a room in range. Each triple
   is tried both ways: y as the longest side (if y ≤ limit), and x as the longest side (if y ≤ 2x, since y is then
   the sum of two sides each at most x).
3. `splits(s, c)` is the split count above.
4. `pythagorean_triples` (in the shared `lib.py`) is Euclid's formula plus multiples. It stops trying m once m² is
   larger than the longest hypotenuse that could be needed, since the hypotenuse is always more than m².
5. `count_cuboids(m)` adds the per-M counts up to m. It's only used by `example()`, which checks the statement's
   1975 (M = 99), 2060 (M = 100) and that 100 is the first M past 2000.

## Complexity

The number of Pythagorean triples with legs up to L grows roughly like L log L, so each round is about
O(L log L). Doubling means all the rounds together cost about twice the last one, which needs L = 3200
(about 7,200 triples). Space is O(L) for the per-M counts.

## Further Thoughts

- **The first version tested every pair.** For each M it tried every s from 2 to 2M and checked whether M² + s² was a
  perfect square with `math.isqrt`. That's about M² ≈ 3.3 million checks: O(M²), 0.77 s. Generating the triples
  directly gives the same count for every M and takes about 0.008 s, roughly 100× faster.
- **Why `isqrt` rather than `sqrt`:** `math.sqrt` uses floating point and can misjudge perfect squares once numbers
  get large. `math.isqrt(n) ** 2 == n` is always exact.
- Euclid's formula also appears in Problems 9 and 75; it now lives in `euler/lib.py` for reuse.

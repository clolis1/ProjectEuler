# Problem 53: Combinatoric Selections

https://projecteuler.net/problem=53

**Answer:** 4075 · **Solution:** `P53.java` · **Runtime:** ~0.03 s

## Problem

There are exactly ten ways of selecting three from five, 12345:

```
123, 124, 125, 134, 135, 145, 234, 235, 245, and 345
```

In combinatorics, we use the notation C(5, 3) = 10.

In general, C(n, r) = n! / (r!(n−r)!), where r ≤ n, n! = n × (n−1) × ... × 3 × 2 × 1, and 0! = 1.

It is not until n = 23, that a value exceeds one-million: C(23, 10) = 1144066.

How many, not necessarily distinct, values of C(n, r) for 1 ≤ n ≤ 100, are greater than one-million?

## In Plain Terms

"How many ways can you choose r things from n?" grows explosively as n gets bigger. For every n up to 100 and
every possible r, work out that number and count how many times it's over a million. Pascal's triangle is a
handy picture: each row is symmetric and biggest in the middle, so the large values sit in a band down the
centre of each row.

## In Theory

C(n, r) is symmetric (C(n, r) = C(n, n − r)) and increases toward the middle of each row. So in row n, the
values above a million form one contiguous block r = k … n − k, contributing n − 2k + 1 entries, where k is the
first r with C(n, r) > 10⁶.

Pascal's rule, C(n, r) = C(n−1, r−1) + C(n−1, r), builds the whole triangle with additions — and capping
values at "over a million" keeps everything small.

## In Code

1. Walk n from 1 to 100, keeping n! as a `BigInteger`.
2. For each r from 1 to n − 1, maintain r! and (n−r)! incrementally, compute n! / (r! × (n−r)!), and count it
   if it's over 1,000,000.

## Complexity

O(n²) binomial coefficients, each involving big-number division on ~150-digit values. Space O(1) big numbers.

## Further Thoughts

Using Pascal's rule with values capped at 1,000,001 needs only `int`s; using the symmetry needs just one scan
per row to find k.

# Problem 74: Digit Factorial Chains

https://projecteuler.net/problem=74

**Answer:** 402 · **Solution:** `P74.java` · **Runtime:** ~0.27 s

## Problem

The number 145 is well known for the property that the sum of the factorial of its digits is equal to 145:

```
1! + 4! + 5! = 1 + 24 + 120 = 145
```

Perhaps less well known is 169, in that it produces the longest chain of numbers that link back to 169; it turns
out that there are only three such loops that exist:

```
169 → 363601 → 1454 → 169
871 → 45361 → 871
872 → 45362 → 872
```

It is not difficult to prove that EVERY starting number will eventually get stuck in a loop. For example,

```
69 → 363600 → 1454 → 169 → 363601 (→ 1454)
78 → 45360 → 871 → 45361 (→ 871)
540 → 145 (→ 145)
```

Starting with 69 produces a chain of five non-repeating terms, but the longest non-repeating chain with a
starting number below one million is sixty terms.

How many chains, with a starting number below one million, contain exactly sixty non-repeating terms?

## In Plain Terms

Replace a number by the sum of its digits' factorials, and repeat. Every chain eventually falls into a loop.
Instead of following each chain to the end from scratch, remember the chain length of every number we've
already seen. When a new chain runs into a remembered number, we can fill in the length of everything on the
new chain at once by counting backward.

## In Theory

This is **memoization** on a functional graph: every number has exactly one successor, so

```
length(n) = 1 + length(next(n))     unless n is on a loop
```

and loop members all share the loop's length. The problem lists every loop, so they're seeded directly:
169, 363601, 1454 → 3; 871, 45361, 872, 45362 → 2; and fixed points (1, 2, 145, 40585) → 1.

## In Code

1. Seed `terms` with the known loops.
2. For each start `i`, follow the chain (summing digit factorials with a switch), collecting unseen numbers in
   `temp`. A number equal to its own digit-factorial sum is recorded as length 1.
3. On hitting a known number, walk `temp` backwards assigning lengths, and count those equal to 60 along the way.

## Complexity

Each number's length is computed once, so O(N × d) overall, where N counts every value reached (at most
6 × 9! = 2,177,280) and d is the digit count. Space O(N) for the map.

## Further Thoughts

Counted lengths are recorded for every chain member, including values above a million that appear mid-chain.
The `temp.get(j) < 1000001` check should be `< 1000000` to match "below one million" exactly; it gives the same
count here.

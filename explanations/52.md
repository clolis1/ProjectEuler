# Problem 52: Permuted Multiples

https://projecteuler.net/problem=52

**Answer:** 142857 · **Solution:** `P52.java` · **Runtime:** ~0.11 s

## Problem

It can be seen that the number, 125874, and its double, 251748, contain exactly the same digits, but in a
different order.

Find the smallest positive integer, x, such that 2x, 3x, 4x, 5x, and 6x, contain the same digits.

## In Plain Terms

We want a number whose double, triple, and so on up to six times all use exactly the same digits, just
shuffled. Since 6x has to have the same number of digits as x, x must start with a 1 — anything starting with
1 and a 7 or higher would grow an extra digit when multiplied by 6. So for each length, only check from 100…0
up to about 166…6. The answer is 142857, a famous number: it's the repeating part of 1/7.

## In Theory

**Digit-count bound**: x and 6x have the same number of digits d iff 10ᵈ⁻¹ ≤ x < 10ᵈ / 6.

**Same digits**: two numbers are digit-permutations iff their sorted digit strings are equal.

Why 142857? It's the repeating block of 1/7 = 0.142857142857…, and multiplying by 2–6 just rotates the cycle:

```
142857 × 2 = 285714
142857 × 3 = 428571
142857 × 4 = 571428
142857 × 5 = 714285
142857 × 6 = 857142
```

That's because 7 is a full reptend prime (see Problem 26).

## In Code

1. For each digit length, loop `x` from 10ⁱ up to 10ⁱ⁺¹ / 6 (as `BigInteger`s).
2. Compare the sorted digits of `x` with those of 2x, 3x, …, 6x, bailing out at the first mismatch.
3. Return the first `x` that passes all five.

## Complexity

O(N) candidates up to the answer, each with constant-size digit checks. Space O(1).

## Further Thoughts

Plain `int`s are plenty here — `BigInteger` only adds overhead. The loop also keeps scanning to the end of the
6-digit range after finding the answer; a `break` would stop it right away.

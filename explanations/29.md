# Problem 29: Distinct Powers

https://projecteuler.net/problem=29

**Answer:** 9183 · **Solution:** `P29.java` · **Runtime:** ~0.02 s

## Problem

Consider all integer combinations of aᵇ for 2 ≤ a ≤ 5 and 2 ≤ b ≤ 5:

```
2²=4,  2³=8,   2⁴=16,  2⁵=32
3²=9,  3³=27,  3⁴=81,  3⁵=243
4²=16, 4³=64,  4⁴=256, 4⁵=1024
5²=25, 5³=125, 5⁴=625, 5⁵=3125
```

If they are then placed in numerical order, with any repeats removed, we get the following sequence of 15
distinct terms:

```
4, 8, 9, 16, 25, 27, 32, 64, 81, 125, 243, 256, 625, 1024, 3125
```

How many distinct terms are in the sequence generated by aᵇ for 2 ≤ a ≤ 100 and 2 ≤ b ≤ 100?

## In Plain Terms

There are 99 × 99 = 9,801 combinations, but some give the same number — 2⁴ and 4² are both 16. The simplest
approach is to compute every one exactly (they're huge, up to 201 digits) and drop them all into a set, which
automatically ignores duplicates. Then just count what's in the set.

## In Theory

Duplicates happen exactly when the bases are powers of a common root: aᵇ = cᵈ requires a = rᵐ and c = rⁿ with
mb = nd. Counting these collisions by hand is fiddly (bases like 2, 4, 8, 16, 32, 64 all share root 2), so
storing the exact values sidesteps the reasoning entirely. 9,801 − 618 duplicates = 9,183.

## In Code

1. For every a and b in 2..100, add `BigInteger.valueOf(a).pow(b)` to a `TreeSet`.
2. Return the set's size.

## Complexity

O(n² log n²) set insertions for n bases, each comparison on numbers of up to ~200 digits. Space O(n²) big
integers.

## Further Thoughts

To avoid big numbers: represent each aᵇ as (root, exponent) — write a = rᵐ with r not a perfect power, and
store the pair (r, m·b). Two powers are equal exactly when those pairs match.

# Problem 50: Consecutive Prime Sum

https://projecteuler.net/problem=50

**Answer:** 997651 · **Solution:** `P50.java` · **Runtime:** ~0.44 s

## Problem

The prime 41, can be written as the sum of six consecutive primes:

```
41 = 2 + 3 + 5 + 7 + 11 + 13
```

This is the longest sum of consecutive primes that adds to a prime below one-hundred.

The longest sum of consecutive primes below one-thousand that adds to a prime, contains 21 terms, and is equal
to 953.

Which prime, below one-million, can be written as the sum of the most consecutive primes?

## In Plain Terms

Pick a starting prime and keep adding the primes after it, one at a time. After each addition, check whether
the running total is itself prime, and remember the longest run that produced one. Stop once the total passes
a million, then try the next starting prime. The best run is 543 primes long, starting at 7, and adds up
to 997,651.

## In Theory

Let S be the running sum from start prime pᵢ through pⱼ. We want the longest run (j − i + 1) with S prime and
S < 10⁶.

The sum of the first 547 primes already exceeds a million, so no run can be longer than 546 terms, and runs
from large starting primes hit the limit after very few terms. That keeps the search small.

## In Code

1. Generate all primes below 10⁶ in a `TreeSet`.
2. For each start prime `i`, add consecutive primes from `primes.tailSet(i)`; whenever the sum is in the set and
   the run is the longest so far, record it.
3. Break when the sum passes 10⁶.

## Complexity

Each start prime does at most ~550 additions before passing the limit, so O(π(n) × L) with L ≈ 550.
Space O(π(n)).

## Further Thoughts

Prefix sums make any run's total a subtraction: S(i, j) = prefix[j] − prefix[i]. Then search run lengths from
longest to shortest and stop at the first prime — usually within the first few start positions.

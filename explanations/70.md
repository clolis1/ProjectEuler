# Problem 70: Totient Permutation

https://projecteuler.net/problem=70

**Answer:** 8319823 · **Solution:** `P70.java` · **Runtime:** ~21 s

## Problem

Euler's Totient function, φ(n) [sometimes called the phi function], is used to determine the number of positive
numbers less than or equal to n which are relatively prime to n. For example, as 1, 2, 4, 5, 7, and 8, are all
less than nine and relatively prime to nine, φ(9) = 6. The number 1 is considered to be relatively prime to every
positive number, so φ(1) = 1.

Interestingly, φ(87109) = 79180, and it can be seen that 87109 is a permutation of 79180.

Find the value of n, 1 < n < 10⁷, for which φ(n) is a permutation of n and the ratio n/φ(n) produces a minimum.

## In Plain Terms

This is Problem 69 turned upside down. Now we want n/φ(n) as *small* as possible, which means n should have as
few prime factors as possible, and large ones. A prime would be ideal, but a prime's φ is n − 1, which can never
be a rearrangement of n's digits. So the best candidates are products of two large primes close to √10⁷ ≈ 3,162.
Among those, find the one whose φ is a digit-shuffle of itself.

## In Theory

n/φ(n) = Π p/(p−1) over the primes dividing n, so it's close to 1 when n has few, large prime factors.

- n prime: φ(n) = n − 1, whose digits differ from n's (only the last digit changes, or a borrow chain), so it's
  never a permutation.
- n = p × q: φ(n) = (p−1)(q−1), and the ratio is smallest when p and q are both near √(10⁷).

The answer is 8319823 = 2339 × 3557, with φ = 8313928 and n/φ(n) ≈ 1.00071.

## In Code

1. For every `i` from 2 to 10⁷, compute `Primes.eulersTotient(i)` by trial-division factoring.
2. Skip `i` if its ratio can't beat the best so far (compared as `double`s).
3. Otherwise check whether `i` and its totient have the same sorted digits; keep the best.

## Complexity

O(n√n) — computing every totient by trial division up to n = 10⁷. That's why it takes ~20 s. Space O(1).

## Further Thoughts

Searching only products of two primes from, say, 1,000 to 5,000 (and checking the digit condition) finds the same
answer in milliseconds. Alternatively, a **totient sieve** computes all φ(n) below 10⁷ in O(n log log n).
